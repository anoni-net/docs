# 一起测周四的移动网络降速：台湾的 OONI 数据还缺三大电信

![一起测周四的移动网络降速](./assets/images/og_home.png){style="border-radius: 10px;box-shadow:1px 1px 0.6rem #00aeff;"}

8 月 13 日周四下午 2 点半，基隆、台北、新北、桃园、新竹市、新竹县、宜兰的移动网络会降速 30 分钟。这是「城镇韧性演习」的一部分，三大电信一起执行，官方公告写明语音通话、短信与小区广播照常，受影响的是视频串流、视频通话、移动支付、云端同步这类高流量服务。公告没有写的是降到多少。中华电信的演练公告从头到尾没有出现任何速率数字，行政院的公告也没有。这 30 分钟的实际样貌，目前只有三家电信自己知道。

<!-- more -->

## 中部场已经示范了会发生什么

8 月 10 日下午 2 点半到 3 点，同样的降速在中部七县市执行过一轮。那 30 分钟结束后，我们去 OONI 的公开数据库查台湾有留下什么。

| 测项 | 该时段全台笔数 | 来源网络 |
|---|---|---|
| `ndt`（连接速度） | 1 | AS131584 台湾智慧光网，固网 |
| `dash`（视频串流质量） | 1 | 同一个固网 ASN |
| `web_connectivity`（网站可达性） | 803 | 几乎全在固网，HiNet 占 593 笔 |

中华电信移动的 AS17421 是 0 笔，远传的 AS9674 是 0 笔。

唯一那笔速度测量执行在固定光纤上，而固网在这场演练里完全不受影响，所以它测到的是一个没有发生降速的网络。中部那 30 分钟等于没有留下任何独立观测。演练结束、带宽恢复，发生过什么就再也查不回来了。

北部场是这次演习的最后一场。

## 台湾的 OONI 数据，四成来自 HiNet

上面那个结果并不意外，它反映的是台湾 OONI 数据长期的形状。近 30 天全台湾有 658,037 笔 `web_connectivity` 测量，分布在 25 个 ASN：

| 网络 | 近 30 天笔数 | 占比 |
|---|---|---|
| AS3462 HiNet | 259,987 | 39.5% |
| 三家移动业者合计 | 23,451 | 3.6% |
| 　└ AS24158 台湾大哥大 | 20,481 | |
| 　└ AS17421 中华电信移动 | 2,375 | |
| 　└ AS9674 远传 | 595 | |

其余的六成多也以固网为主，台湾智慧光网、StarVerse、DaDa Broadband 各有数万笔，另外还有几所大学的校园网络。

换到这次真正需要的性能测项，数字更少。近 30 天全台湾只有 1,025 笔 `ndt`，其中中华电信移动 16 笔、远传 4 笔。同期 `web_connectivity` 是 658,037 笔，性能测量的密度大约是它的万分之十五。

所以现在要说明「台湾的网络环境如何」，能拿出来的数据主要反映家用固定宽带的状况。台湾有超过三千万的移动号码，多数人一天里大半时间是透过移动网络上网，这一块在公开观测数据里几乎是空白。

还有一个更麻烦的问题。台湾大哥大同时经营移动与固网，中华电信也是，所以看到一笔 AS24158 的测量，光凭数据判断不出它来自手机还是家里的调制解调器。刻意在已知时段、已知情境下执行测量，才能产生标签明确、后续拿得出来用的数据。

## 为什么要三家一起测

移动网络的测量平常很难做出有意义的比较，因为各家用户在不同时间、不同地点、不同基站底下，测到的差异可能来自任何原因。要比较业者之间的行为，需要一个三家同时面对同一个条件的时刻。

周四下午 2 点半就是这种时刻。同一个 30 分钟、同一组县市、同一道行政指令，三家电信各自去实作降速。官方没有公布各家怎么做、降到多少、是否一致。这些差异只有一种方法看得出来，就是三家的用户在同一时间各自测量，而 OONI 会自动把每笔测量标上 ASN。

单独一家测得再密，也只能得到那一家的曲线。三家一起才构成对照。

## 这 30 分钟的数据能用来做什么

**一、产生一份时间标签明确的降速数据集。** 全球的网络降速研究最难的一环，是不知道降速从几点开始、几点结束、涵盖哪里。多数案例是用户先察觉变慢，研究者事后回推，时间边界永远模糊。这次是政府预告的演练，日期、时段、县市、业者全部公开，30 分钟的边界清清楚楚。这种带 ground truth 的样本在公开数据集里很少见，对 OONI 与 M-Lab 的研究者都有价值。

**二、替台湾的移动网络建立基线。** 有了平时与降速中的对照，未来真的发生非预期的网络劣化时，才有东西可以比对。没有基线的话，任何一次异常都只能停在「大家觉得变慢」。

**三、独立验证官方的说法。** 公告说语音、短信、文字传输正常，只有高流量服务受影响。这条界线实际落在哪里，需要独立测量才能检查。这不是为了挑毛病，公民社会有能力自己验证公共措施的实际效果，本身就是韧性的一部分。

**四、看规避工具会不会被波及。** 带宽被压低时，Tor、Psiphon 这类工具还能不能建立连接，是这个社群长期在追的题目。这 30 分钟刚好是一个现成的测试场。

## 周四要做的三件事

**一、关掉 Wi-Fi，改用移动数据。** 这条做错的话，后面全部白做。固网与 Wi-Fi 在这次演练中完全不受影响，中部场唯一那笔测量就是这样浪费掉的。

**二、运行 OONI Probe 内建的 Performance 测试。** 打开 App，选 Performance 那张卡片，按运行。那张卡片里就包含 `ndt` 与 `dash` 两个测项，正好是测降速需要的。这张卡片在 Android 与 iOS 都有。

!!! tip "不要用 OONI Run 链接"

    直觉会想发一条 [OONI Run v2](../../tools/ooni-run-v2.md) 链接给大家点，这次请不要。OONI Run v2 目前只支持 Android，iOS 用户收到链接会用不了。内建的 Performance 卡片两个平台都有，直接请大家点那张最简单。

**三、运行三次，不是一次。**

| 时间 | 用途 |
|---|---|
| 14:15 | 降速前的基线 |
| 14:35 | 降速中 |
| 15:10 | 恢复后 |

没有 14:15 那笔基线，14:35 测到的数字没有比较对象，也就没有意义。

还没安装的人，[OONI Probe](https://ooni.org/install/){target="_blank"} 在 App Store、Google Play 与 F-Droid 都有，开源免费。不熟悉这个工具的话，可以先看[什么是 OONI](../../tools/what-is-ooni.md)。

!!! warning "降速中上传失败是正常的"

    测量结果需要上传，而降速期间带宽本来就被压低，上传可能会卡住或失败。不需要重复运行，OONI Probe 会把结果排入队列，等网络恢复后自动补传。

行有余力的话，14:35 那一轮可以多运行一次 Circumvention 卡片，里面含 Tor 与 Psiphon 的连接测试，能看出降速对规避工具的影响。

## 隐私上要知道的事

OONI 的测量结果全部公开，内容包含所处的 ASN 与时间戳记，不包含个人 IP 地址。ASN 加上时间可以推知大致的位置与所用的电信商。这次是政府预告的公开演练，参与者是北部七县市的一般用户，暴露程度很低。这一点仍然要说明白，愿不愿意留下这笔记录由你自己决定。

## 之后怎么用 OONI 佐证研究

这次的号召是一个具体事件，方法本身可以重复使用。OONI 的数据有三个入口，用途差很多：

- **[OONI Explorer](https://explorer.ooni.org/){target="_blank"}**：网页界面，适合查单笔测量、看某个国家或 ASN 的趋势，不需要写程序。
- **Aggregation API**：`https://api.ooni.org/api/v1/aggregation`，免验证免密钥，可以依国家、测项、ASN、时间切分做统计。本文所有数字都出自这里。
- **AWS S3 公开数据集**：`ooni-data-eu-fra`，逐笔原始 JSON，适合需要看测量细节或做大规模分析的研究。取用方式与 CSV 输出格式写在 [ASN 观测数据撷取与分析](../../community/asn-coverage-howto.md)，社群维护的撷取程序也在那页。

要判断某个问题该用哪个测项，可以查 [OONI 测项速查表](../../community/ooni-nettests-map.md)，那页整理了每个测项测什么、规格状态，以及台湾有没有数据。想看台湾的 ASN 覆盖现况，见 [ASN 自治网络观测数据分析](../../taiwan/ooni-asn-coverage.md)。

用这些数据时有两件事要注意。

**anomaly 不等于封锁。** OONI 的 `anomaly` 只代表测试没有照预期完成，成因包含审查、网络不稳、ISP 暂时故障，以及测试程序本身的问题。拿 anomaly 比率直接当封锁率会产生假指控。以 `tor` 测项近 30 天的实测为例，加拿大 21.2%、瑞士 22.2%、新西兰 41.1%，全是没有审查的国家。中段的数值属于噪声，只有极端高的那几个对得上现实。

**授权是 CC BY-NC-SA 4.0。** OONI 发布的测量数据禁止商业使用，衍生内容需以相同授权释出。引用数据时要标注来源，把 OONI 数据混进其他来源产生新的数据档，会让整份成品都受这个授权拘束。

## 一起来

需要的就是周四下午三个时间点、各按一次运行。以现在的密度来说，每家电信只要有 10 支手机参与，就已经是数量级的改善。

欢迎转给住在或工作在北部七县市的朋友，特别是中华电信与远传的用户，这两家目前的性能测量近乎于零。有问题或想一起整理结果的人，欢迎到[社群 Matrix 公开 room](../../community/tools.md) 讨论。
