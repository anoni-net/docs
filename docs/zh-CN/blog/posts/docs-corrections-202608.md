# 撤回自己写过的话：文档站近两周的修正纪录

![文档站近两周的修正纪录](./assets/images/post-update.png){style="border-radius: 10px;box-shadow:1px 1px 0.6rem #00aeff;"}

7/27 到 8/07 之间，文档站并入 45 个 PR，三语系共新增 45 页。新增的部分列在网站上就看得到，比较少被纪录的是另一半的工作：把已经上线的内容改掉，甚至整段撤回。

<!-- more -->

## 程式补完之后，发现文档是错的

[OONI 测量资料结构导览](../../community/ooni-data-format.md)上线时就写着，最小的一步是在逐行解析时多取 `test_keys.blocking`，统计就能从测量笔数延伸到各 ASN 的异常分布。程式一直没有做，那是文档与程式之间唯一一处说了没做的地方。八月初补上栏位统计，新数据一产出就推翻了站上另一篇文章的叙述。

[OONI 怎么判定一个网站被封锁](../../community/ooni-blocking-determination.md)原本写着抽查 40 笔异常测量，`dns` 31 笔、`tcp_ip` 6 笔、`http-failure` 3 笔、`http-diff` 0 笔，并据此说台湾没有出现重导向到封锁告示页的样态。改用 2026-08-05 往前 24 小时的全量数据（22,105 笔）重算之后，两个说法都不成立：

| 判定 | 笔数 | 占比 |
|---|---:|---:|
| `false` | 21,029 | 95.13% |
| `none` | 512 | 2.32% |
| `tcp_ip` | 312 | 1.41% |
| `dns` | 150 | 0.68% |
| `http-failure` | 67 | 0.30% |
| `http-diff` | 35 | 0.16% |

`tcp_ip` 是 `dns` 的两倍以上，`http-diff` 也确实存在，问题出在那 40 笔的来源，它取自 measurements API 的异常清单，该清单有自己的排序，当成随机样本使用会失准。页面上补了一则警示纪录这次更正，因为同样的陷阱别人也会遇到。

台湾的 `http-diff` 与印尼的封锁告示页属于不同状况。抽查 4 小时内的 15 笔，`body_proportion` 全部落在 `0.004` 到 `0.21` 之间，Probe 取得的内容远短于对照组，与告示页逼近 `1` 的样态相反。成因需要逐笔查验证据层，文档因此只陈述观察到的样态，不下结论。

## 查不到出处的就撤掉

[出差与研讨会的数位准备](../../scenarios/asia-travel.md)在八月初做了一次全页查证更新，六路平行查核之后撤回三处查无实据的叙述。

- **香港自 3/30 起的边境解锁权「不以国安嫌疑为前提」**。该说法只出现在旅游资讯聚合网站，各家对生效日（3/28 或 3/30）与罚则（6 个月或 1 年）互相矛盾，政府宪报、律政司资料与第一线媒体都查不到对应文本。页面收敛成 3/23 的国安法修订（`Legal Notice 27 of 2026`）一项，并写明不予采信的理由。
- **日本境外购买的 eSIM 不受新规范**。森・滨田松本法律事务所对此点明确标注「文書に明記されていません」。原本被写成一条可以依赖的建议。
- **马来西亚 ONSA 首周处理 1,500 则以上贴文**。原始来源的 1,583 是 2025/1/1 至 11/30 的仇恨内容下架请求总数，时间早于 ONSA 生效。

同一次更新换掉了南韩段落的来源。原本引用的 Cybernews 无署名、无引用，且该站与 VPN 联盟有利益冲突，改用 Lumen Database `#73101162` 与韩国时报，过期的「20 万件」也更新为 2024 年审议 356,945 件。香港的风险层级由中升到高。

## 同一页自己跟自己矛盾

[互动与呈现](../../games/index.md)区的总览页在上线隔天被查核抓到四处事实错误，其中两处是文档跟自己打架。

文中写地球仪画面上有流星，原始码里的 `buildSky()` 只画静态星空与银河带，搜寻 `meteor`、`流星`、`comet` 全部零命中。带亮头的彗星属于另一件作品 onion-rendezvous，两件被混在一起写。另一处把「两条电路在中途某台中继相遇」当成 Tor 通则，该叙述只适用于连线 .onion 服务，而同一页的作品卡片写的是正确版本。

其余两处是文档与数据对不上，「每份数据档都带有四个栏位」的说法在 `cables.json` 上就不成立，该档缺了 `sourceUrl` 与 `licenseUrl`。处理方式选择把数据补齐，`tools/gen_cables.py` 一并修改，而非把文档说法改弱。另一处「`tools/` 只使用 Python 标准库加上 curl」漏掉了 `fix_trunk_land.mjs` 是 Node、`publish_games_data.sh` 是 shell。

另有三处写得太满，其中「任何一步错位，匿名性就不成立」已改为保守叙述，因为 Tor 的顺序错乱通常导致连线失败，而匿名性也会因为流量关联、出口监控这类与顺序无关的因素被打破。ASN「由一家业者掌管」的说法，被同一个专案里产生快照的脚本自己的注解否定，该注解写明 ASN 可能由个人申请。「八十个国家」写死精确整数，快照重新产生就会过时，改为约八十个并标明数字取自最近一次快照。

## 推荐的替代工具已经易主

七月底到八月初补了八页读者提问的内容，随后用结构、逐句、目标读者三个角色平行审过一次，抓出六项会误导读者的问题。

[怎么维持多个网络身分](../../basics/multiple-identities.md)推荐 Raivo 作为 Authy 的替代品，而 Raivo 在 2023 年 7 月被 Mobime 收购，新东家的隐私政策纳入广告追踪器与 log 收集。同一行还写着 Authy 停止维护所以要换，前后自相矛盾。修订后只保留 Aegis 与 2FAS，并给出开源、可汇出备份、经营者未换手三个判断标准，比列品牌耐久。

同一页另有两处问题，「在现有 Gmail 开一个全新帐号（不绑手机）」实务上做不到，改为说明主流免费信箱在注册阶段就要求手机验证，同装置同 IP 开的帐号也可能被服务商自行关联。虚拟门号原本只警告 WhatsApp 封锁，补上两个关键风险：付费刷卡会把两层身分接回去，号码会被回收再配发给下一个人，对方之后能用简讯重设你的帐号。

[社群平台怎么收集你的数据](../../basics/platform-tracking.md)写「大规模研究没有找到偷录音的证据」，容易被读成已经证明没有，补上「没有找到证据跟证明不存在是两回事」，并加入 2024 年 Cox Media Group 的 Active Listening 推销简报事件（Google 随后将该公司移出合作伙伴计划，该公司否认实际聆听）。

[社运行动者的数位准备](../../scenarios/activist.md)的「预付卡购买时不要用实名身分证办」跟出差页新增的十四地实名对照直接矛盾，而新章节还两次把读者导向那一页。

## 英文读者看到的是转址画面

Cloudflare 近 90 天的数据（排除子网域与 bot）显示英文版占文档站流量 25.9%，440 次浏览里只有 70 次（16%）落在真正的文章，290 次落在分类目录页，80 次是 404。

追查后有三个成因，第一个是 `redirect_maps` 有四条规则的来源就是现存的英文页，mkdocs-redirects 会在该路径产生 stub 盖掉真正的页面，线上实测那四页全部只剩转址画面。第二个是有三条转址在英文内容存在的情况下指向目录页。最后是 2026-05-09 的导览重构，该次 commit 从 `docs/en/` 删除 17 个文件、新增 0 个，约 11.5 万字元，设定档注解写明「dropped pages redirect to the nearest live section index」。

依实测流量还原了五篇，落在真正文章的比例由 16% 提升到 64%。剩下 12 篇被删的英文内容与 18% 的 404 尚未处理。

## 规则写在规范里，工具没有实作

贡献者百科写着口语词改书面语，而 `docs_style_lint.py` 只针对其中一个字实作了规则。全站扫出 605 处其他口语词，站台自己的工具对现况回报 0 error、0 warn。规则存在、工具没有，内容自然会偏离规范。

七月底那次清扫处理 669 处、158 个文件，同时补上六条 linter 规则，全部列为 warn，因为替换词要看语境，不该让机器直接改。清扫过程中机械取代造成两处实质损害，都已修复并补进例外清单：

- 「主讲」被换成「主提到」，破坏了议程页两个语系共 20 处介绍。原因是排除清单只挡后面的字，没挡前面的「主」。
- 「没搞清楚」被换成「没处理清楚」，理解与处理属于两回事。<!-- docs-style-lint: disable-line -->

七月底另一支 PR 收尾时发现，比对规则只涵盖正体字，简体对应字完全没有被检查，zh-CN 等于没有这条规则。扫过全站之后欠债比预期少，需要检视的只有 3 处，查完都是正当用法。真正的收获是补上了首套回归测试，因为 linter 是全站写作规范的守门员，却没有任何测试。这类覆盖不全的问题人工抽样看不出来，抽到的样本恰好都在覆盖范围内。目前 49 个案例，每条规则都有应挡与不应挡两组，繁简并列。

八月初再补上「这」字的密度标准，起因是校稿时实际使用的判准只留在 commit 讯息里，下次写新页不会生效，于是把判准写进贡献者百科，并把可机器判断的部分做成 `zhe-repeat` 规则。距离门槛 8 个字是对全站 429 篇校准出来的，放宽到 10 会开始收进正当用法。全文密度需要语意判断，刻意留给人工。在此之前另有一次全站清理，扫出 99 个文件、266 段有堆叠，逐段改写。

## 感谢两位社群伙伴

近两周的 45 个 PR 里有两个来自社群伙伴。

wu858430049 补上了 [BECOME_ANONI](../../community/become-anoni.md) 协定的简中版。正本放在 repo 根目录，位置比照 zh-TW，文档页用 snippets 嵌入以维持单一来源。同一个 PR 顺手修掉两个会挡住页面的设定问题：`mkdocs_cn.yml` 的 `pymdownx.snippets` 缺少 `base_path`，以及一条把该路径导向社群首页的旧转址规则。

ChihChengLiang 更新了 [COSCUP 2026](../../activity/coscup-2026.md) 隐私支付实作工作坊的介绍。原本写着不需自备电脑、跟着看就好，实际上现场已备妥模拟网络与模拟链，鼓励参加者携带电脑实际操作。过时的说明会让有意参与实作的人准备不足。

两个 PR 的共同点是都修掉了会让读者做出错误判断的内容。[贡献者百科](../../community/contributor-handbook.md)写明了送 PR 的流程与写作规范，欢迎更多人以同样的方式参与。

## 为什么把这些写出来

站台的主题是隐私与安全，读者依照文档的建议调整自己的行为。一句过时的法规叙述、一个已经易主的 app 推荐，后果由读者承担。抽样得到的分布写成通则，读者无从分辨那是 40 笔还是 22,105 笔得到的结论。

同一段时间新增的内容包括八页读者提问的回答、四篇 OONI 技术文档、互动区的台湾基础设施图层，以及 .onion 版建置纳入 CI，全部列在网站上。若读到与事实不符的内容，欢迎到 [GitHub](https://github.com/anoni-net/docs/issues){target="_blank"} 开一个 issue 或直接送 PR，我们会查证后更新。
