另一种常见的场合：NGO 的工作人员把捐款页面的网址贴进 LINE 群组，那个网址是从电子报里复制出来的，带着 `utm_source` 与 `mc_eid`。收到的人点进去，后台看到的不只是有人捐款，还包括是哪一封信、经过谁转发。清过的网址捐款照样成立，只是少了那一层可以回溯到谁的痕迹。

## 那串参数在告诉谁什么

你从 Facebook 点开一篇文章再复制网址，得到的东西长这样：

```
https://example.com/article?fbclid=IwAR3xK9mQ...
```

`fbclid` 是 Meta 给那一次点击的识别码。你把它贴进群组，每个点进去的人都会带着同一个 ID 回到 Meta，于是同一个 ID 把整串点击记录串回 Meta，看得出这则链接是谁分享的、有多少人点、那些人是谁。你以为只是分享一篇文章，实际上把整个群组串了起来。

电子报的 `utm_source` 也一样，转发出去等于告诉收件人你订了哪份电子报。`mc_eid` 更直接，那是 Mailchimp 的收件人识别码，对得回你的电子邮件地址。

## 转址包装

Google 搜索结果的链接指向的并不是你看到的那个网址：

```
https://www.google.com/url?q=https%3A%2F%2Fanoni.net%2F&sa=U&ved=...
```

直接复制贴给别人的话，对方点进去会先经过 Google 一次。Facebook 的 `l.php` 与 Instagram 的外链也是同样做法。这个工具会把包装拆掉，只留真正的目的地。

## 只移除认得出来的参数

移除的逻辑是白名单：只拿掉清单里认得出来的追踪参数，其余一律保留。

反过来做的话，`?v=`（YouTube 的视频 ID）、`?page=2`、`?q=` 会一起被砍掉，你会取得一个打不开或指向错误内容的网址，而且不会联想到是清理工具改坏的，只会觉得对方给错了链接。测试里有一整组案例守着这件事。

每个被拿掉的参数旁边都会说明是谁在追，那比单纯吐一个干净网址有用：下次你在别的地方看到 `gclid`，就知道那是什么。

## 短网址不展开

`t.co`、`bit.ly` 这类要连上去才知道指向哪里。这一页刻意不做，因为那会把你想清理的网址送到第三方服务器上，正好是这个工具要避免的事。

要查短网址的目的地，用 [Tor Browser](../tools/what-is-tor.md) 开一次是比较安全的做法，那样至少对方看不到你的 IP。

## 离线可用

跟这一区其他工具一样，程序存进设备之后没有网络也能用。把网络关掉试一次，它照样清得出来，那也表示你贴进去的网址不可能被送到任何地方。
