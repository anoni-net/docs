## 什么时候用得上

[Metadata 是什么](../basics/metadata.md)那篇提到，照片里带着拍摄时间、相机型号与 GPS 坐标，而「上传照片前先去 EXIF」是任何人现在就能做的低成本防护。

问题在于怎么去。线上的清除工具几乎都要先把文件传上去，而会需要清 metadata 的人，正是最不该把原始文件交出去的人。

这一页在你的浏览器里改，文件不离开设备。清完的是新的一份，原始文件不会被动到。

## 拿掉什么，留下什么

JPEG 的 metadata 全部住在文件头那几段 marker segment 里，PNG 的则各自是独立的 chunk。两种都是整段拿掉，不碰图像本身。

| 拿掉 | 里面是什么 |
|---|---|
| EXIF（JPEG 的 `APP1`、PNG 的 `eXIf`） | 拍摄时间、相机型号、GPS 坐标，还有没被裁切过的缩略图 |
| XMP | Adobe 系列软件写的描述，常含地点与作者 |
| IPTC 与 Photoshop 字段（`APP13`） | 说明、作者、关键词 |
| 注释字段（JPEG 的 `0xFFFE`、PNG 的 `tEXt`、`zTXt`、`iTXt`） | 文件里夹带的任意文字 |
| 修改时间（PNG 的 `tIME`） | 上次存档的时间 |

| 留着 | 为什么 |
|---|---|
| ICC 色彩描述文件 | 拿掉的话颜色会偏掉。这种描述文件多半是 sRGB 这类标准的，识别力低 |
| Adobe 色彩转换标记（`APP14`） | CMYK 的 JPEG 少了它，颜色会反过来 |
| JFIF 基本信息（`APP0`） | 少了它有些看图程序会抱怨 |
| PNG 的图像 chunk（`IHDR`、`PLTE`、`IDAT`、`tRNS`、`gAMA`、`sRGB`、`iCCP` 等） | 这些是图本身，拿掉就解不开或变样 |

每一段的去留都会列在画面上，含段落代号与比特数。工具不替你决定这件事的细节，看得到才算数。

## 清完的图跟原图完全一样

这一页不重新编码。JPEG 的压缩数据从 SOS 标记开始一路照抄到文件尾，一个比特都没动。

重新编码的工具做不到这件事。每一次重新压缩都会损失画质，而且会在输出里留下自己的处理痕迹，那本身又变成一种可辨识的特征。用 mat2 清过的文件看得出来是 mat2 清的。

也因为是无损的，清完之后文件通常只小一点点。一张 630 KB 的照片清掉完整的 EXIF 之后是 629 KB，那 140 个比特组就是原本记着相机型号与坐标的地方。

## 不支持的格式

**HEIC/HEIF**：iPhone 默认拍出来就是这个格式，它的容器结构复杂得多，这一页还做不到。在 iPhone 上可以到「设置 → 相机 → 格式」选「最兼容」，之后拍的就是 JPEG。已经拍好的可以用 AirDrop 或邮件传给自己，那个过程多半会转成 JPEG。

**WebP、GIF、PDF、视频**：目前都不支持。这一页处理 JPEG 与 PNG。PDF 的 metadata 散在多个地方，视频的则在容器结构里，两种都需要另外处理。

## 这一页不做的事

不做人脸模糊。那需要人脸检测模型，跟清除 metadata 是完全不同的一件事，也不该用同一个工具的名义混在一起。

不做的还有：拿掉 metadata 不等于照片就安全了。画面里的门牌、路标、制服、窗外的景色，那些都在图像本身，这一页不会动到它们。分享之前自己看一遍。

## 清完之后会实际打开一次

清好的文件会在浏览器里实际载入一次再交给你。如果这一页的程序把文件改坏了，那一步会拦下来并且明白告诉你，不会让你拿着一份打不开的照片去交差。你的原始文件全程没有被动到。

## 离线可用

跟这一区其他工具一样，程序存进设备之后没有网络也能用。断网时照样能用，就是「文件没有偷偷送出去」最直接的证明。
