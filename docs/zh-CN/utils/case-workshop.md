# :material-presentation: 工作坊现场要发东西给大家

## 二十个人，一个下午

场地借到了，投影仪接得上。参加的人自己带设备来，手机、笔记本、平板都有，操作系统至少三种。

要发下去的东西有几样。一个教材网址，一段 Tor bridge 设置，一份几 KB 的配置文件，还有一份四十几 MB 的教材 PDF。

现场的 Wi-Fi 是主办方的，密码写在墙上。它能不能传文件是一回事，你愿不愿意让二十个人的设备为了拿文件而连上同一个不属于你的网络是另一回事。

需要装软件的方案在这个场合成本很高。公开的培训准备指南建议，要让学员装一个新工具就得预留 90 分钟，而这个下午总共只有三小时。

## 很长的字符串印成 QR code

教材网址、onion 地址、bridge 设置这几样的共同点是又长又容易打错，而且没有一个人打得对第一次。

用 [QR code 生成器](qrcode.md)把字符串变成 QR code，下载成 SVG。SVG 放大不会糊，投影到幕上或印成 A4 贴在墙边都清楚。

过程中不经过任何服务器。印出来的纸质版在断网的场地照样能用，而且下一场还可以再用同一张。

bridge 那种一行八十几个字符的设置尤其该用这个方式发。现场一个一个念给大家打，错字率高得惊人，而打错的人会以为是 bridge 失效。

## 几 KB 的文件用屏幕跟镜头传

配置文件、密钥、签名这种几 KB 到几十 KB 的东西，用 [QR code 影格串流](qr-stream.md)。文件切成一连串 QR code 在你的屏幕上轮流播放，对方用相机读回来拼成原文件。

两台设备之间没有配对、没有共用网络、没有服务器。你的笔记本举着屏幕，参加者拿手机对着拍，就这样。

这个通道很慢，一秒钟大约送一到三 KB，工具本身挡下超过 512 KB 的文件。那个数字量的是人的耐性，512 KB 用默认设置要播四分二十秒，而且收齐通常不只一轮。

收齐之后不需要再另外比对哈希。工具发出时就把原文件的 SHA-256 放进第一张，收的一端拼完自己算一次，画面上直接告诉你对不对得上。

## 大文件还是 U 盘

四十几 MB 的教材 PDF 超出影格串流的范围，硬做只会让二十个人举着手机站十分钟。

现场有网络可以用的话，[OnionShare](../tools/onionshare.md) 是设计来做这件事的。没有网络就用 U 盘，一台一台插过去。

U 盘这条路多一个步骤。你在自己电脑上先用[文件哈希比对](hash.md)算出教材的 SHA-256，把那一串投影在幕上。参加者拷完之后自己算一次，跟幕上那串对一下。

这一步防的是拷贝过程出错，也防 U 盘在传递途中被换过内容。二十个人轮流插同一支 U 盘，中间发生过什么你不会知道。算哈希不需要装东西，[文件哈希比对](hash.md)那一页在断网的场地照样打得开，几 GB 的文件也算得动。

## 这条路径不只用在工作坊

任何一个要把东西交给眼前这些人的场合都适用：

- 社团或读书会现场交换设置与链接
- 摊位上把地址给走过来的人，纸质 QR code 放在桌上
- 两个人在咖啡厅交换密钥，不通过店家的 Wi-Fi
- 场地断网时把原本要线上发的东西改成当场发

这几个工具都在你的浏览器里执行，内容不发出去。页面存进设备之后没有网络也能用，事前先存好，见[离线阅读](../offline.md)。
