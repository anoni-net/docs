## 什麼時候用得上

[Metadata 是什麼](../basics/metadata.md)那篇提到，照片裡帶著拍攝時間、相機型號與 GPS 座標，而「上傳照片前先去 EXIF」是任何人現在就能做的低成本防護。

問題在於怎麼去。線上的清除工具幾乎都要先把檔案傳上去，而會需要清 metadata 的人，正是最不該把原始檔交出去的人。

這一頁在你的瀏覽器裡改，檔案不離開裝置。清完的是新的一份，原始檔不會被動到。

兩種常見的處境：

- **剛搬到新住處，想傳一張照片給朋友報平安。** 手機拍照預設會把 GPS 座標寫進檔案裡。朋友看到的是一張照片，有心找的人看到的是一組座標。傳出去之前清一次，畫面完全不受影響。
- **在現場拍了畫面要投稿給媒體。** 照片裡的拍攝時間與座標合起來，指得出是誰在什麼時候站在哪裡。清掉之後編輯台收到的還是同一張圖。

## 拿掉什麼，留下什麼

照片檔案裡，影像本身跟描述用的欄位是分開存放的。這一頁把描述那幾段整段拿掉，影像那部分一個位元都不碰。

| 拿掉 | 裡面是什麼 |
|---|---|
| EXIF | 拍攝時間、相機型號、GPS 座標，還有一張沒被裁切過的縮圖 |
| XMP | Adobe 系列軟體寫的描述，常含地點與作者 |
| IPTC 與 Photoshop 欄位 | 說明、作者、關鍵字 |
| 註解欄位 | 檔案裡夾帶的任意文字 |
| 修改時間 | 上次存檔的時間 |

| 留著 | 為什麼 |
|---|---|
| 色彩描述檔 | 拿掉的話顏色會偏掉。這種描述檔多半是 sRGB 這類標準的，識別力低 |
| 色彩轉換標記 | 印刷用的 CMYK 檔案少了它，顏色會反過來 |
| 基本相容資訊 | 少了它有些看圖程式會抱怨 |
| 影像本身 | 拿掉就解不開或變樣 |

那張沒被裁切過的縮圖值得單獨提。你把照片裁掉一半再傳出去，EXIF 裡那張縮圖可能還是原本的完整畫面。

畫面上會逐項列出這次拿掉與留下的東西，含各自佔幾個位元組，還有檔案格式裡對應的段落代號。工具不替你決定去留，看得到才算數。

## 影片是一樣的道理

MP4 與 MOV 也在處理範圍裡。手機拍的影片跟照片一樣會記錄拍攝地點、裝置型號與時間，而且影片通常更難察覺，因為多數人不會去看影片的屬性。

這種檔案是一層包一層的結構，描述欄位住在其中一層。整段拿掉不需要碰壓縮過的影音資料，跟照片是同一種做法，清完的影片解碼出來跟原檔一個位元都不差。

三個地方會被清掉：

- 使用者資料區：標題、作者、拍攝地點座標、裝置型號
- 編碼器名稱與版本：那會指出你用什麼軟體或哪一款手機處理過
- 軌道的處理器名稱：不同平台寫法不同，等於一個平台指紋

### 有一種痕跡清不掉

編碼器會把自己的版本寫進壓縮資料本身。那一段不是描述欄位，是影音資料的一部分，位置跟畫面內容混在一起。

要清掉只能重新編碼，而重新編碼會損失畫質，也只是把舊編碼器的痕跡換成新的。這一頁不做那件事，但會把掃到的字串列出來告訴你，不讓你以為清乾淨了。

## PDF 是另一種處理方式

PDF 也在範圍裡，但做法跟前面兩種不同。

照片與影片可以直接把某一段剪掉，PDF 不行。那個格式的每個物件在交叉索引表裡都記著自己在檔案裡的位置，拿掉一段之後後面全部位移，整張表要重算。而且 PDF 1.5 之後常見的做法是把好幾個物件壓進同一段壓縮資料，從外面連內容都看不到。

所以這一部分交給 [pdf-lib](https://github.com/Hopding/pdf-lib){target="_blank"}（MIT 授權，原封不動放在 `utils/vendor/` 底下），由它負責解析與重寫，這一頁只決定拿掉哪些欄位。

清掉的是：

- 文件標題、作者、主旨、關鍵字
- 製作這份文件的軟體，那一欄常含作業系統與版本。用瀏覽器列印成 PDF 的話，裡面會是完整的瀏覽器識別字串
- 建立與修改時間
- XMP 描述區，地點、作者與編輯歷史都可能記在那裡

### 拿掉引用不等於拿掉內容

XMP 那一段有個陷阱值得說。把文件目錄裡指向 XMP 的那個引用刪掉之後，重新存檔，那段內容仍然完整留在檔案裡，只是沒有人指向它。用文字搜尋工具打開還是找得到作者跟地點。

要真的清掉必須把那個物件本身從文件裡移除，工具就是這樣處理的。`tools/test_stripmeta.mjs` 有一項測試專門守著它。

### PDF 沒辦法保證無損

照片與影片那邊，壓縮資料一個位元都沒動，清完的檔案解出來跟原檔完全相同。PDF 做不到這個保證，因為整份檔案是重寫的。

實測上頁面內容不會重新排版，渲染出來的畫面跟原檔逐像素相同。但如果你的 PDF 有表單、數位簽章或特殊的互動元件，重寫之後不一定完全保留。重要的檔案先留一份原始檔。

## 清完的圖跟原圖完全一樣

這一頁不重新編碼。影像與影音資料從檔案裡的固定位置開始照抄，一個位元都沒動。

重新編碼的工具做不到無損。每一次重新壓縮都會損失畫質，而且會在輸出裡留下自己的處理痕跡，那本身又變成一種可辨識的特徵。用 mat2 清過的檔案看得出來是 mat2 清的。

也因為是無損的，清完之後檔案通常只小一點點。一張 630 KB 的照片清掉完整的 EXIF 之後是 629 KB，那 140 個位元組就是原本記著相機型號與座標的地方。

## 不支援的格式

**HEIC/HEIF**：iPhone 預設拍出來就是這個格式，它的容器結構複雜得多，這一頁還做不到。在 iPhone 上可以到「設定 → 相機 → 格式」選「最相容」，之後拍的就是 JPEG。已經拍好的可以用 AirDrop 或郵件傳給自己，那個過程多半會轉成 JPEG。

**WebP、GIF**：目前不支援。

## 這一頁不做的事

不做臉部模糊。那需要人臉偵測模型，跟清除 metadata 是完全不同的一件事，也不該用同一個工具的名義混在一起。

不做的還有：PDF 裡的註解與附件各自可能帶著作者與時間，這一頁只處理文件層級的描述欄位，遇到那種檔案會在畫面上說一聲。

拿掉 metadata 也不等於檔案就安全了。畫面裡的門牌、路標、制服、窗外的景色，那些都在影像本身，這一頁不會動到它們。分享之前自己看一遍。

## 清完之後會實際打開一次

清好的檔案會在瀏覽器裡實際載入一次再交給你。影片會等到時間長度讀得出來為止，那是改壞影片最典型的症狀。如果這一頁的程式把檔案改壞了，那一步會攔下來並且明白告訴你，不會讓你拿著一份打不開的照片離開。你的原始檔全程沒有被動到。

## 離線可用

跟這一區其他工具一樣，程式存進裝置之後沒有網路也能用。斷網時照樣能用，就是「檔案沒有偷偷送出去」最直接的證明。
