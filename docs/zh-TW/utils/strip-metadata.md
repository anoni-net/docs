## 什麼時候用得上

[Metadata 是什麼](../basics/metadata.md)那篇提到，照片裡帶著拍攝時間、相機型號與 GPS 座標，而「上傳照片前先去 EXIF」是任何人現在就能做的低成本防護。

問題在於怎麼去。線上的清除工具幾乎都要先把檔案傳上去，而會需要清 metadata 的人，正是最不該把原始檔交出去的人。

這一頁在你的瀏覽器裡改，檔案不離開裝置。清完的是新的一份，原始檔不會被動到。

## 拿掉什麼，留下什麼

JPEG 的 metadata 全部住在檔頭那幾段 marker segment 裡，PNG 的則各自是獨立的 chunk。兩種都是整段拿掉，不碰影像本身。

| 拿掉 | 裡面是什麼 |
|---|---|
| EXIF（JPEG 的 APP1、PNG 的 `eXIf`） | 拍攝時間、相機型號、GPS 座標，還有沒被裁切過的縮圖 |
| XMP | Adobe 系列軟體寫的描述，常含地點與作者 |
| IPTC 與 Photoshop 欄位（APP13） | 說明、作者、關鍵字 |
| 註解欄位（JPEG 的 `0xFFFE`、PNG 的 `tEXt`、`zTXt`、`iTXt`） | 檔案裡夾帶的任意文字 |
| 修改時間（PNG 的 `tIME`） | 上次存檔的時間 |

| 留著 | 為什麼 |
|---|---|
| ICC 色彩描述檔 | 拿掉的話顏色會偏掉。這種描述檔多半是 sRGB 這類標準的，識別力低 |
| Adobe 色彩轉換標記（APP14） | CMYK 的 JPEG 少了它，顏色會反過來 |
| JFIF 基本資訊（APP0） | 少了它有些看圖程式會抱怨 |
| PNG 的影像 chunk（`IHDR`、`PLTE`、`IDAT`、`tRNS`、`gAMA`、`sRGB`、`iCCP` 等） | 這些是圖本身，拿掉就解不開或變樣 |

每一段的去留都會列在畫面上，含段落代號與位元組數。工具不替你決定這件事的細節，看得到才算數。

## 清完的圖跟原圖完全一樣

這一頁不重新編碼。JPEG 的壓縮資料從 SOS 標記開始一路照抄到檔尾，一個位元都沒動。

重新編碼的工具做不到這件事。每一次重新壓縮都會損失畫質，而且會在輸出裡留下自己的處理痕跡，那本身又變成一種可辨識的特徵。用 mat2 清過的檔案看得出來是 mat2 清的。

也因為是無損的，清完之後檔案通常只小一點點。一張 630 KB 的照片清掉完整的 EXIF 之後是 629 KB，那 140 個位元組就是原本記著相機型號與座標的地方。

## 不支援的格式

**HEIC/HEIF**：iPhone 預設拍出來就是這個格式，它的容器結構複雜得多，這一頁還做不到。在 iPhone 上可以到「設定 → 相機 → 格式」選「最相容」，之後拍的就是 JPEG。已經拍好的可以用 AirDrop 或郵件傳給自己，那個過程多半會轉成 JPEG。

**WebP、GIF、PDF、影片**：目前都不支援。這一頁處理 JPEG 與 PNG。PDF 的 metadata 散在多個地方，影片的則在容器結構裡，兩種都需要另外處理。

## 這一頁不做的事

不做臉部模糊。那需要人臉偵測模型，跟清除 metadata 是完全不同的一件事，也不該用同一個工具的名義混在一起。

不做的還有：拿掉 metadata 不等於照片就安全了。畫面裡的門牌、路標、制服、窗外的景色，那些都在影像本身，這一頁不會動到它們。分享之前自己看一遍。

## 清完之後會實際打開一次

清好的檔案會在瀏覽器裡實際載入一次再交給你。如果這一頁的程式把檔案改壞了，那一步會攔下來並且明白告訴你，不會讓你拿著一份打不開的照片去交差。你的原始檔全程沒有被動到。

## 離線可用

跟這一區其他工具一樣，程式存進裝置之後沒有網路也能用。斷網時照樣能用，就是「檔案沒有偷偷送出去」最直接的證明。
