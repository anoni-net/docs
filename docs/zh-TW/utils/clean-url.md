NGO 的工作人員把捐款頁面的網址貼進 LINE 群組，網址是從電子報裡複製出來的，帶著 `utm_source` 與 `mc_eid`。收到的人點進去，後台取得的不只是有人捐款，還包括是哪一封信、經過誰轉發。清過的網址捐款照樣成立，只是少了可以回溯到誰的痕跡。

## 網址後面那串參數洩漏了什麼

你從 Facebook 點開一篇文章再複製網址，得到的會是這種形狀：

```
https://example.com/article?fbclid=IwAR3xK9mQ...
```

`fbclid` 是 Meta 給該次點擊的識別碼。你把它貼進群組，每個點進去的人都帶著同一個 ID 回到 Meta，於是連結是誰分享的、有多少人點、點的人是誰，都串成同一筆記錄。

電子報的 `utm_source` 也一樣，轉發出去等於讓收件人知道你訂了哪份電子報。`mc_eid` 更直接，是 Mailchimp 的收件人識別碼，對得回你的電子郵件地址。

## 轉址包裝

Google 搜尋結果的連結，實際指向的網址跟你看到的不一樣：

```
https://www.google.com/url?q=https%3A%2F%2Fanoni.net%2F&sa=U&ved=...
```

直接複製貼給別人的話，對方點進去會先經過 Google 一次。Facebook 的 `l.php` 與 Instagram 的外部連結也是同樣做法。工具會把包裝拆掉，只留真正的目的地。

## 只移除認得出來的參數

移除的邏輯是白名單：只拿掉清單裡認得出來的追蹤參數，其餘一律保留。

反過來做的話，`?v=`（YouTube 的影片 ID）、`?page=2`、`?q=` 會一起被砍掉，你會取得一個打不開或指向錯誤內容的網址，而且不會聯想到是清理工具改壞的，只會覺得對方給錯了連結。YouTube 影片、分頁、搜尋這類常見網址都測過，需要的參數不會被誤刪。

每個被拿掉的參數旁邊都會標示是誰在追，比單純吐一個乾淨網址有用。下次你在別的地方看到 `gclid`，就知道是什麼。

## 短網址不展開

`t.co`、`bit.ly` 等短網址得連上去才知道指向哪裡。清理器刻意不做展開，因為展開等於把你想清理的網址送到第三方伺服器，正是清理網址要避免的事。

要查短網址的目的地，用 [Tor Browser](../tools/what-is-tor.md) 開一次比較安全，對方至少看不到你的 IP。

## 離線可用

跟這一區其他工具一樣，程式存進裝置之後沒有網路也能用。把網路關掉試一次，照樣清得出來，代表你貼進去的網址不可能被送到任何地方。
