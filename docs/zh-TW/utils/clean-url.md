另一種常見的場合：NGO 的工作人員把捐款頁面的網址貼進 LINE 群組，網址是從電子報裡複製出來的，帶著 `utm_source` 與 `mc_eid`。收到的人點進去，後台看到的不只是有人捐款，還包括是哪一封信、經過誰轉發。清過的網址捐款照樣成立，只是少了那一層可以回溯到誰的痕跡。

## 那串參數在告訴誰什麼

你從 Facebook 點開一篇文章再複製網址，得到的東西長這樣：

```
https://example.com/article?fbclid=IwAR3xK9mQ...
```

`fbclid` 是 Meta 給那一次點擊的識別碼。你把它貼進群組，每個點進去的人都會帶著同一個 ID 回到 Meta，於是同一個 ID 把整串點擊記錄串回 Meta，看得出這則連結是誰分享的、有多少人點、那些人是誰。你以為只是分享一篇文章，實際上把整個群組串了起來。

電子報的 `utm_source` 也一樣，轉發出去等於告訴收件人你訂了哪份電子報。`mc_eid` 更直接，那是 Mailchimp 的收件人識別碼，對得回你的電子郵件地址。

## 轉址包裝

Google 搜尋結果的連結指向的並不是你看到的那個網址：

```
https://www.google.com/url?q=https%3A%2F%2Fanoni.net%2F&sa=U&ved=...
```

直接複製貼給別人的話，對方點進去會先經過 Google 一次。Facebook 的 `l.php` 與 Instagram 的外連也是同樣做法。這個工具會把包裝拆掉，只留真正的目的地。

## 只移除認得出來的參數

移除的邏輯是白名單：只拿掉清單裡認得出來的追蹤參數，其餘一律保留。

反過來做的話，`?v=`（YouTube 的影片 ID）、`?page=2`、`?q=` 會一起被砍掉，你會取得一個打不開或指向錯誤內容的網址，而且不會聯想到是清理工具改壞的，只會覺得對方給錯了連結。測試裡有一整組案例守著必要參數不被誤刪。

每個被拿掉的參數旁邊都會說明是誰在追，那比單純吐一個乾淨網址有用：下次你在別的地方看到 `gclid`，就知道那是什麼。

## 短網址不展開

`t.co`、`bit.ly` 這類要連上去才知道指向哪裡。這一頁刻意不做，因為那會把你想清理的網址送到第三方伺服器上，正好是這個工具要避免的事。

要查短網址的目的地，用 [Tor Browser](../tools/what-is-tor.md) 開一次是比較安全的做法，那樣至少對方看不到你的 IP。

## 離線可用

跟這一區其他工具一樣，程式存進裝置之後沒有網路也能用。把網路關掉試一次，它照樣清得出來，那也表示你貼進去的網址不可能被送到任何地方。
