# :material-presentation: 工作坊現場要發東西給大家

## 二十個人，一個下午

場地借到了，投影機接得上。參加的人自己帶裝置來，手機、筆電、平板都有，作業系統至少三種。

要發下去的東西有幾樣。一個教材網址，一段 Tor bridge 設定，一份幾 KB 的設定檔，還有一份四十幾 MB 的教材 PDF。

現場的 Wi-Fi 是主辦方的，密碼寫在牆上。它能不能傳檔案是一回事，你願不願意讓二十個人的裝置為了拿檔案而連上同一個不屬於你的網路是另一回事。

需要裝軟體的方案在這個場合成本很高。公開的訓練準備指南寫著，要讓學員裝一個新工具就得預留 90 分鐘，而這個下午總共只有三小時。

## 很長的字串印成 QR code

教材網址、onion 位址、bridge 設定這幾樣的共同點是又長又容易打錯，而且沒有一個人打得對第一次。

用 [QR code 產生器](qrcode.md)把字串變成 QR code，下載成 SVG。SVG 放大不會糊，投影到幕上或印成 A4 貼在牆邊都清楚。

過程中不經過任何伺服器。印出來的紙本在斷網的場地照樣能用，而且下一場還可以再用同一張。

bridge 設定一行八十幾個字元，尤其該用 QR code 發。現場一個一個唸給大家打很容易出錯，而打錯的人會以為是 bridge 失效。

## 幾 KB 的檔案用螢幕跟鏡頭傳

設定檔、金鑰、簽章這種幾 KB 到幾十 KB 的東西，用 [QR code 影格串流](qr-stream.md)。檔案切成一連串 QR code 在你的螢幕上輪流播放，對方用相機讀回來拼成原檔。

兩台裝置之間沒有配對、沒有共用網路、沒有伺服器。你的筆電舉著螢幕，參加者拿手機對著拍，就這樣。

這個通道很慢，一秒鐘大約送一到三 KB，工具本身擋下超過 512 KB 的檔案。那個數字量的是人的耐性，512 KB 用預設設定要播四分二十秒，而且收齊通常不只一輪。

收齊之後不需要再另外比對雜湊。工具送出時就把原檔的 SHA-256 放進第一張，收的一端拼完自己算一次，畫面上直接告訴你對不對得上。

## 大檔案改用隨身碟送

四十幾 MB 的教材 PDF 超出影格串流的範圍，硬做只會讓二十個人舉著手機站十分鐘。

現場有網路可以用的話，[OnionShare](../tools/onionshare.md) 是設計來做這件事的。沒有網路就用隨身碟，一台一台插過去。

隨身碟這條路多一個步驟。你在自己電腦上先用[檔案雜湊比對](hash.md)算出教材的 SHA-256，把那一串投影在幕上。參加者拷完之後自己算一次，跟幕上那串對一下。

比對雜湊防的是拷貝過程出錯，也防隨身碟在傳遞途中被換過內容。二十個人輪流插同一支隨身碟，中間發生過什麼你不會知道。算雜湊不需要裝東西，[檔案雜湊比對](hash.md)那一頁在斷網的場地照樣打得開，幾 GB 的檔案也算得動。

## 這條路徑不只用在工作坊

任何一個要把東西交給眼前這些人的場合都適用：

- 社團或讀書會現場交換設定與連結
- 攤位上把位址給走過來的人，紙本 QR code 放在桌上
- 兩個人在咖啡廳交換金鑰，不透過店家的 Wi-Fi
- 場地斷網時把原本要線上發的東西改成當場發

這幾個工具都在你的瀏覽器裡執行，內容不送出去。頁面存進裝置之後沒有網路也能用，事前先存好，見[離線閱讀](../offline.md)。
