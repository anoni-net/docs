# 撤回自己寫過的話：文件站近兩週的修正紀錄

![文件站近兩週的修正紀錄](./assets/images/post-update.png){style="border-radius: 10px;box-shadow:1px 1px 0.6rem #00aeff;"}

7/27 到 8/07 之間，文件站併入 45 個 PR，三語系共新增 45 頁。新增的部分列在網站上就看得到，比較少被記錄的是另一半的工作：把已經上線的內容改掉，甚至整段撤回。

<!-- more -->

## 程式補完之後，發現文件是錯的

[OONI 測量資料結構導覽](../../community/ooni-data-format.md)上線時就寫著，最小的一步是在逐行解析時多取 `test_keys.blocking`，統計就能從測量筆數延伸到各 ASN 的異常分布。程式一直沒有做，那是文件與程式之間唯一一處說了沒做的地方。八月初補上欄位統計，新資料一產出就推翻了站上另一篇文章的敘述。

[OONI 怎麼判定一個網站被封鎖](../../community/ooni-blocking-determination.md)原本寫著抽查 40 筆異常測量，`dns` 31 筆、`tcp_ip` 6 筆、`http-failure` 3 筆、`http-diff` 0 筆，並據此說台灣沒有出現重導向到封鎖告示頁的樣態。改用 2026-08-05 往前 24 小時的全量資料（22,105 筆）重算之後，兩個說法都不成立：

| 判定 | 筆數 | 佔比 |
|---|---:|---:|
| `false` | 21,029 | 95.13% |
| `none` | 512 | 2.32% |
| `tcp_ip` | 312 | 1.41% |
| `dns` | 150 | 0.68% |
| `http-failure` | 67 | 0.30% |
| `http-diff` | 35 | 0.16% |

`tcp_ip` 是 `dns` 的兩倍以上，`http-diff` 也確實存在，問題出在那 40 筆的來源，它取自 measurements API 的異常清單，該清單有自己的排序，當成隨機樣本使用會失準。頁面上補了一則警示記錄這次更正，因為同樣的陷阱別人也會遇到。

台灣的 `http-diff` 與印尼的封鎖告示頁屬於不同狀況。抽查 4 小時內的 15 筆，`body_proportion` 全部落在 `0.004` 到 `0.21` 之間，Probe 取得的內容遠短於對照組，與告示頁逼近 `1` 的樣態相反。成因需要逐筆查驗證據層，文件因此只陳述觀察到的樣態，不下結論。

## 查不到出處的就撤掉

[出差與研討會的數位準備](../../scenarios/asia-travel.md)在八月初做了一次全頁查證更新，六路平行查核之後撤回三處查無實據的敘述。

- **香港自 3/30 起的邊境解鎖權「不以國安嫌疑為前提」**。該說法只出現在旅遊資訊聚合網站，各家對生效日（3/28 或 3/30）與罰則（6 個月或 1 年）互相矛盾，政府憲報、律政司資料與第一線媒體都查不到對應文本。頁面收斂成 3/23 的國安法修訂（`Legal Notice 27 of 2026`）一項，並寫明不予採信的理由。
- **日本境外購買的 eSIM 不受新規範**。森・濱田松本法律事務所對此點明確標註「文書に明記されていません」。原本被寫成一條可以依賴的建議。
- **馬來西亞 ONSA 首週處理 1,500 則以上貼文**。原始來源的 1,583 是 2025/1/1 至 11/30 的仇恨內容下架請求總數，時間早於 ONSA 生效。

同一次更新換掉了南韓段落的來源。原本引用的 Cybernews 無署名、無引用，且該站與 VPN 聯盟有利益衝突，改用 Lumen Database `#73101162` 與韓國時報，過期的「20 萬件」也更新為 2024 年審議 356,945 件。香港的風險層級由中升到高。

## 同一頁自己跟自己矛盾

[互動與呈現](../../games/index.md)區的總覽頁在上線隔天被查核抓到四處事實錯誤，其中兩處是文件跟自己打架。

文中寫地球儀畫面上有流星，原始碼裡的 `buildSky()` 只畫靜態星空與銀河帶，搜尋 `meteor`、`流星`、`comet` 全部零命中。帶亮頭的彗星屬於另一件作品 onion-rendezvous，兩件被混在一起寫。另一處把「兩條電路在中途某台中繼相遇」當成 Tor 通則，該敘述只適用於連線 .onion 服務，而同一頁的作品卡片寫的是正確版本。

其餘兩處是文件與資料對不上，「每份資料檔都帶有四個欄位」的說法在 `cables.json` 上就不成立，該檔缺了 `sourceUrl` 與 `licenseUrl`。處理方式選擇把資料補齊，`tools/gen_cables.py` 一併修改，而非把文件說法改弱。另一處「`tools/` 只使用 Python 標準庫加上 curl」漏掉了 `fix_trunk_land.mjs` 是 Node、`publish_games_data.sh` 是 shell。

另有三處寫得太滿，其中「任何一步錯位，匿名性就不成立」已改為保守敘述，因為 Tor 的順序錯亂通常導致連線失敗，而匿名性也會因為流量關聯、出口監控這類與順序無關的因素被打破。ASN「由一家業者掌管」的說法，被同一個專案裡產生快照的腳本自己的註解否定，該註解寫明 ASN 可能由個人申請。「八十個國家」寫死精確整數，快照重新產生就會過時，改為約八十個並標明數字取自最近一次快照。

## 推薦的替代工具已經易主

七月底到八月初補了八頁讀者提問的內容，隨後用結構、逐句、目標讀者三個角色平行審過一次，抓出六項會誤導讀者的問題。

[怎麼維持多個網路身分](../../basics/multiple-identities.md)推薦 Raivo 作為 Authy 的替代品，而 Raivo 在 2023 年 7 月被 Mobime 收購，新東家的隱私政策納入廣告追蹤器與 log 收集。同一行還寫著 Authy 停止維護所以要換，前後自相矛盾。修訂後只保留 Aegis 與 2FAS，並給出開源、可匯出備份、經營者未換手三個判斷標準，比列品牌耐久。

同一頁另有兩處問題，「在現有 Gmail 開一個全新帳號（不綁手機）」實務上做不到，改為說明主流免費信箱在註冊階段就要求手機驗證，同裝置同 IP 開的帳號也可能被服務商自行關聯。虛擬門號原本只警告 WhatsApp 封鎖，補上兩個關鍵風險：付費刷卡會把兩層身分接回去，號碼會被回收再配發給下一個人，對方之後能用簡訊重設你的帳號。

[社群平台怎麼收集你的資料](../../basics/platform-tracking.md)寫「大規模研究沒有找到偷錄音的證據」，容易被讀成已經證明沒有，補上「沒有找到證據跟證明不存在是兩回事」，並加入 2024 年 Cox Media Group 的 Active Listening 推銷簡報事件（Google 隨後將該公司移出合作夥伴計畫，該公司否認實際聆聽）。

[社運行動者的數位準備](../../scenarios/activist.md)的「預付卡購買時不要用實名身分證辦」跟出差頁新增的十四地實名對照直接矛盾，而新章節還兩次把讀者導向那一頁。

## 英文讀者看到的是轉址畫面

Cloudflare 近 90 天的資料（排除子網域與 bot）顯示英文版佔文件站流量 25.9%，440 次瀏覽裡只有 70 次（16%）落在真正的文章，290 次落在分類目錄頁，80 次是 404。

追查後有三個成因，第一個是 `redirect_maps` 有四條規則的來源就是現存的英文頁，mkdocs-redirects 會在該路徑產生 stub 蓋掉真正的頁面，線上實測那四頁全部只剩轉址畫面。第二個是有三條轉址在英文內容存在的情況下指向目錄頁。最後是 2026-05-09 的導覽重構，該次 commit 從 `docs/en/` 刪除 17 個檔案、新增 0 個，約 11.5 萬字元，設定檔註解寫明「dropped pages redirect to the nearest live section index」。

依實測流量還原了五篇，落在真正文章的比例由 16% 提升到 64%。剩下 12 篇被刪的英文內容與 18% 的 404 尚未處理。

## 規則寫在規範裡，工具沒有實作

貢獻者百科寫著口語詞改書面語，而 `docs_style_lint.py` 只針對其中一個字實作了規則。全站掃出 605 處其他口語詞，站台自己的工具對現況回報 0 error、0 warn。規則存在、工具沒有，內容自然會偏離規範。

七月底那次清掃處理 669 處、158 個檔案，同時補上六條 linter 規則，全部列為 warn，因為替換詞要看語境，不該讓機器直接改。清掃過程中機械取代造成兩處實質損害，都已修復並補進例外清單：

- 「主講」被換成「主提到」，破壞了議程頁兩個語系共 20 處介紹。原因是排除清單只擋後面的字，沒擋前面的「主」。
- 「沒搞清楚」被換成「沒處理清楚」，理解與處理屬於兩回事。<!-- docs-style-lint: disable-line -->

七月底另一支 PR 收尾時發現，比對規則只涵蓋正體字，簡體對應字完全沒有被檢查，zh-CN 等於沒有這條規則。掃過全站之後欠債比預期少，需要檢視的只有 3 處，查完都是正當用法。真正的收穫是補上了首套回歸測試，因為 linter 是全站寫作規範的守門員，卻沒有任何測試。這類覆蓋不全的問題人工抽樣看不出來，抽到的樣本恰好都在覆蓋範圍內。目前 49 個案例，每條規則都有應攔與不應攔兩組，繁簡並列。

八月初再補上「這」字的密度標準，起因是校稿時實際使用的判準只留在 commit 訊息裡，下次寫新頁不會生效，於是把判準寫進貢獻者百科，並把可機器判斷的部分做成 `zhe-repeat` 規則。距離門檻 8 個字是對全站 429 篇校準出來的，放寬到 10 會開始收進正當用法。全文密度需要語意判斷，刻意留給人工。在此之前另有一次全站清理，掃出 99 個檔案、266 段有堆疊，逐段改寫。

## 感謝兩位社群夥伴

近兩週的 45 個 PR 裡有兩個來自社群夥伴。

wu858430049 補上了 [BECOME_ANONI](../../community/become-anoni.md) 協定的簡中版。正本放在 repo 根目錄，位置比照 zh-TW，文件頁用 snippets 嵌入以維持單一來源。同一個 PR 順手修掉兩個會擋住頁面的設定問題：`mkdocs_cn.yml` 的 `pymdownx.snippets` 缺少 `base_path`，以及一條把該路徑導向社群首頁的舊轉址規則。

ChihChengLiang 更新了 [COSCUP 2026](../../activity/coscup-2026.md) 隱私支付實作工作坊的介紹。原本寫著不需自備電腦、跟著看就好，實際上現場已備妥模擬網路與模擬鏈，鼓勵參加者攜帶電腦實際操作。過時的說明會讓有意參與實作的人準備不足。

兩個 PR 的共同點是都修掉了會讓讀者做出錯誤判斷的內容。[貢獻者百科](../../community/contributor-handbook.md)寫明了送 PR 的流程與寫作規範，歡迎更多人以同樣的方式參與。

## 為什麼把這些寫出來

站台的主題是隱私與安全，讀者依照文件的建議調整自己的行為。一句過時的法規敘述、一個已經易主的 app 推薦，後果由讀者承擔。抽樣得到的分布寫成通則，讀者無從分辨那是 40 筆還是 22,105 筆得到的結論。

同一段時間新增的內容包括八頁讀者提問的回答、四篇 OONI 技術文件、互動區的台灣基礎設施圖層，以及 .onion 版建置納入 CI，全部列在網站上。若讀到與事實不符的內容，歡迎到 [GitHub](https://github.com/anoni-net/docs/issues){target="_blank"} 開一個 issue 或直接送 PR，我們會查證後更新。
