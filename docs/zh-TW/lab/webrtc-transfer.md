# :material-lan-connect: 裝置之間直接傳檔

兩台裝置連上同一個網路，檔案直接從一台到另一台。中間沒有伺服器，文件站這一側拿不到任何一個位元組。

這一頁屬於[實驗區](index.md)，目的是量數字，不是拿來日常用的工具。

## 為什麼要量這個

文件站的離線內容目前只能透過網路更新。[QR code 影格串流](../utils/qr-stream.md)每秒送一到三 KB，傳一份幾 MB 的離線內容不成立。

同一個區網裡的直接連線快得多，代價是兩台裝置要先交換一段描述，而那一步通常靠一台伺服器。把那段描述壓到夠小，就能用 QR code 交換，整條路不需要任何伺服器。這一頁先量那段描述有多大，以及實際傳輸有多快。

## 兩台裝置怎麼測

兩台連上同一個網路，自己開的熱點最可控。

1. 兩台都按第一區的「開始」，第二區出現各自的 QR code，相機也跟著打開
2. 拿其中一台的相機對準另一台的螢幕。掃到的那一台會自動回應，第二區換成回應用的 QR code
3. 另一台的相機對準它，掃到就連上了

不必先約定誰發起，誰先掃到誰都可以。第一次打開相機時瀏覽器會問能不能用相機，允許才掃得了。相機畫面在這一頁裡解碼，不會送到任何地方。

第三區可以改用前鏡頭。兩支手機螢幕對螢幕拿著，兩邊的前鏡頭同時看得到對方，一來一回在同一個動作裡完成。前鏡頭多半是定焦的，要離多遠才讀得到，也是這一輪要量的數字。

相機不能用的時候，第二區底下的文字框可以整段複製交給對方，貼進第三區按套用，效果一樣。

連上之後任一邊都可以送東西過去。收的一端會算 SHA-256 跟來源比對，數字一致才算這一次成功。

## 三台以上

第三台不必跟每一台都掃一次，跟已經連上的任何一台互掃就好。連上之後，裝置之間會交換各自連著哪些裝置，還沒連上的兩台由中間那一台轉交連線描述，自動補上連線。第四區標出每一條連線是掃 QR code 連上的，還是經由哪一台介紹。

送東西時會同時送給每一台已經連上的裝置，第五區分開列出每一台的耗時與比對結果。同一個 Wi-Fi 頻道由幾台分著用，每一台的速度會比一對一時慢，慢多少也是要量的數字。

## 已知會失敗的情況

公共 Wi-Fi 普遍開啟裝置隔離，同一個網路裡的裝置連不到彼此，而那正好是最需要這個功能的場合。遇到這種網路，頁面會停在候選蒐集完成卻連不上。

Tor Browser 把 WebRTC 整個關掉，因為它會洩漏你真正的 IP。那個版本開不了這一頁的功能。

企業網路與部分訪客網路會擋掉多播，瀏覽器用來認出對方的 `.local` 名稱因此解析不到。

## 這一頁不送任何資料

頁面沒有 fetch、XMLHttpRequest、sendBeacon 與 WebSocket，也不載入外部資源。連線設定裡沒有 STUN 也沒有 TURN，連得上就是靠同一個區網裡的候選位址。

檔案內容只在連上的裝置之間流動，經由介紹建立連線時，連線描述也只經過已經連上的那一台。匯出紀錄的時候，IP 與 mDNS 名稱會先遮掉再寫進檔案。

## 測完請回報

傳之前先在第五區那一欄填上這次的環境，例如「自架熱點，Mac Chrome 對 iPhone Safari」。那一行會跟著每一筆紀錄一起匯出，之後整理結果時才對得起來。

按「匯出紀錄」存下 JSON，貼到 [issue #553](https://github.com/anoni-net/docs/issues/553){target="_blank"}。每一台各匯出一份，收送兩側的耗時才都有。

失敗的結果一樣有用。判準之一就是「失敗要多快說得出來」，卡在轉圈三分鐘的體驗跟直接說不支援，對現場的人差別很大。
