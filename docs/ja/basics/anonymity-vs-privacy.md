# :material-incognito-circle: 匿名・プライバシー・仮名・機密

この 4 つの言葉は同義語のように使われますが、同義語ではありません。ある道具が非常に高い**機密性**を持ちながら（内容は誰にも読めない）、**匿名性**はまったくない（誰が誰と話しているかは丸見え）ということがあります。あるアカウントが**仮名性**を持ちながら（他人からは「Alice」としてしか見えない）、**プライバシー**はゼロ（投稿もいいねもすべて公開）ということもあります。言葉の境界が曖昧なままだと、たいてい仕事に合わない道具を選び、守るべきでないものを守る労力を使うことになります。

このページでは 4 つを並べ、具体例で境界線を引きます。

!!! info "このページがある理由"

    主要な自衛教材はそれぞれの概念を単独では丁寧に説明していますが、4 つを一枚に並べた比較はほとんどありません。anoni.net はアジア太平洋の中国語圏で活動するボランティア コミュニティで、このページは地域の状況を踏まえて書かれています。体系的な入門としては [EFF Surveillance Self-Defense](https://ssd.eff.org/){target="_blank"} と [Privacy Guides](https://www.privacyguides.org/){target="_blank"} が定番の出発点であり、本文中の掘り下げリンクもそちらを指しています。

## 4 つの概念を一覧で

| 概念 | 答える問い | 一行の定義 |
|---|---|---|
| 匿名性 | *これをやっているのは誰か* | 行為と実在の身元とのつながりが切れている状態。観察者は「誰かが何かをした」ことは見えても、それが誰かは言えない。 |
| プライバシー | *自分に関する情報を誰が見るかを自分で決められるか* | 個人情報をどこまで開示するかの選択権を本人が握っている状態。誰に、いつ、どの程度まで。 |
| 仮名性 | *この文脈では、どの人格として振る舞っているか* | 実在の身元から切り離された、安定したハンドル名で行動する状態。同じハンドル名の行為どうしは結びつけられるが、本人には届かない。 |
| 機密性 | *内容を読めるのは権限のある人だけか* | メッセージやファイルが意図した受信者だけに読める状態。通信中も保存中も、権限のない相手には露出しない。 |

## 同じ 4 つを、具体的に

### 手紙を出す

- **匿名性**：差出人名も返信先住所も書かない手紙。受け取った人は内容を読み、誰かが書いたことは分かりますが、それが誰かは分かりません。
- **プライバシー**：友人だけが読むと想定して出す手紙。誰かが蒸気で開封したなら、それはプライバシーの侵害であって、匿名性の侵害ではありません。
- **仮名性**：ペンネームで署名します。そのペンネームの手紙どうしは束ねられますが、身分証の名前には結びつきません。
- **機密性**：封をして、輸送中に中身を読まれないようにします。これは誰が出したか、誰が受け取ったか、何通あったかとは独立した性質です。

### 掲示板に書き込む

- **匿名性**：登録なし。投稿のたびに新しい、結びつけられない身元になります。観察者に見えるのは「誰かが書き込んだ」ことだけです。
- **プライバシー**：実名で登録しつつ、どの投稿を公開し、どれを友人限定にするかを自分で決めます。
- **仮名性**：`cat_lover_7` として登録し、すべての投稿がそのハンドル名にぶら下がります。長く見ている読者は、あなたが誰かを知らないまま `cat_lover_7` の癖や生活リズムを組み立てられます。
- **機密性**：ダイレクト メッセージが端末間で暗号化されており、掲示板のサーバーは本文を読めません。

ここでの要点はこうです。**匿名性と仮名性の違いは、実名を使うかどうかではなく、同一の身元における行為どうしが結びつけられるかどうかにあります。** 匿名性は一つ一つの行為が結びつかないことを要求します。仮名性は行為どうしが結びつくことを受け入れたうえで、それが実在の人物に届かないことだけを守ります。

### メッセージング ツール

それぞれの道具がどの性質に寄っているかを簡単に見ます。用語はツールのセクションで詳しく扱うので、馴染みがなくても心配いりません。

- **Signal** は**機密性**に強く、メッセージは端末間で暗号化され、サーバーは中身を読めません。一方で**匿名性には弱い**です。登録が電話番号に紐づいており、誰が誰と連絡しているか（メタデータ）は通信経路を握る者からは依然として見えます。アジア太平洋の多くの法域では SIM の契約が法律で実在の身元に紐づけられているため[^1]、この弱さは字面以上に効いてきます。アカウントの背後にある電話番号が、しばしば法的な身元そのものになるからです。
- **Onion サービス**（Tor ネットワークの内側で動く、`.onion` で終わるアドレスのサイト）は**匿名性**に強く、誰が何を見たかをたどるのは困難です。ただしサービスがログインを要求した瞬間に**仮名性**の話になります。行為がアカウントに紐づき、結びつけられるようになるからです。
- **PGP で暗号化したメール**（メールを暗号化する一般的な方法）は**機密性**に強く、本文は暗号化されています。**匿名性には弱い**です。送信者と受信者のアドレスはヘッダーに載るため、誰と誰が話しているかは露出しています。

## いちばん多い誤解は、機密性を匿名性だと思うこと

「端末間暗号化を使ったから匿名だ」は最も頻繁に見る誤りです。暗号化は**内容**を仲介者から守りますが、**誰が誰と、いつ、どのくらいの頻度で、どれだけの時間**話したかは通常は暗号化されません。仮に暗号化されていても、サーバーはその形を観察できます。多くの脅威モデルでは、このメタデータだけで交友関係と行動パターンを再構成するのに十分です。詳しい論拠は EFF の [Why Metadata Matters](https://ssd.eff.org/module/why-metadata-matters){target="_blank"} にあります。

## 正しい言葉を選ぶと、選ぶ道具が変わる

- 情報源を守る記者に必要なのは**匿名性**です。身元が割れた情報源は現実の危険にさらされるので、内容の機密性だけでは足りません。
- パートナーと写真を共有するときに必要なのは**プライバシー**です。写真が二人の外へ広がらないことが問題であって、匿名性は関係ありません。相手には自分だと知っていてほしいわけです。
- 扱いの難しいテーマの掲示板に長く書き続けるなら**仮名性**です。実在の身元から切り離したまま積み上げられる評判が必要になります。完全な匿名性では読者の信頼を得にくくなります。
- 弁護士とやり取りするなら**機密性**です。内容が二人の間に留まればよく、匿名性も仮名性も当てはまりません。弁護士は代理のためにあなたが誰かを知る必要があります。

言葉を選び間違えると道具も選び間違えます。匿名性の問題を Signal で解こうとする、機密性の問題を Tor で解こうとする、プライバシーの問題をペンネームで解こうとする。どれも、実際に直面していたリスクがそのまま通り抜ける隙間を残します。

## 4 つすべてを満たす道具はない

実際には、4 つの性質を同時に最大化する道具はほとんどありません。互いに引っ張り合うからです。

- 強い匿名性は、毎回ゼロから始まるため、継続的な関係を築きにくくなります。
- 強い仮名性は関係を積み上げられますが、同じハンドル名の下はすべて結びつきます。
- 強い機密性は事前の鍵交換や身元確認を必要とすることが多く、匿名性とはある程度の緊張関係にあります。
- 強いプライバシーは「これを誰に見せるか」の細かい制御を必要とし、たいていはアカウント、権限、プラットフォームの規約を伴います。

道具を選ぶ前に、*この*仕事で守るべきものは何かを問い、そのうえで取捨を決めてください。この問いこそが[脅威モデリング](https://ssd.eff.org/module/your-security-plan){target="_blank"}の中核にあたります。

## 日本から読む場合の注記

このページの枠組み自体は地域を問いませんが、**電話番号が身元と結びつく度合い**は法域によって違います。日本では、携帯電話不正利用防止法（正式名称は「携帯音声通信事業者による契約者等の本人確認等及び携帯音声通信役務の不正な利用の防止に関する法律」）により、携帯電話の契約時に事業者が本人確認を行い、その記録を作成し保存することが義務づけられています[^2]。

つまり、日本国内で契約した番号で Signal や同種のアプリを使う場合、そのアカウントを支えている番号は、事業者の手元では本人確認記録に結びついています。これは Signal の暗号化が弱いという話ではありません。**機密性は強いままで、匿名性の側に穴がある**という、このページで扱ってきた区別がそのまま当てはまる、というだけの話です。番号と身元を切り離したいのであれば、暗号化されたメッセンジャーを選ぶことではなく、匿名性を設計目標に掲げた別の層の道具を検討することになります。
