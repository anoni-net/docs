# :material-shield-search: 脅威モデルの立て方

匿名性やプライバシーの話でいちばん多い落とし穴は、道具を答えだと思い込み、「自分は結局のところ何を防ごうとしているのか」を整理する段階を飛ばすことです。「Tor を使えば安全ですか」「Signal と Telegram はどちらが安全ですか」「VPN は入れるべきですか」。こうした問いの背後で欠けているのは、構造化された判断の枠組みです。脅威モデルがその枠組みにあたります。

脅威モデルは、定期的に見返す気になる程度の小さなリストです。どれだけ形式を整えるかは重要ではなく、継続して見返せることが重要です。道具を選ぶとき、行動を決めるとき、リスクを見積もるときに、3 つの基本的な問いに答えられるようにするためのものです。

## 3 つの基本的な問い

脅威モデルを立てるとは、本質的にこの 3 問に答えることです。

1. **何を守るのか**（資産）
2. **誰から守るのか。相手にはどんな能力があるのか**（敵対者）
3. **その保護のために、どこまでコストを払えるのか**（トレードオフ）

3 つとも欠かせません。1 問目がないと、重要でないものに保険をかけることになります。2 問目がないと、蚊を大砲で撃つか、大砲を蚊取り線香で防ごうとすることになります。3 問目がないと、続けられない体制を組んでしまい、数日で放り出すことになります。

## 1 問目：何を守るのか

「資産」は企業向けの言葉に聞こえますが、要するに他人に取られたくない、見られたくない、壊されたくないものです。個人にとってはかなり具体的に書けます。

- **情報**：身元に関わるもの（本名、住所、職業、家族の居場所）、内容に関わるもの（私的な会話、未公開の写真、書きかけの原稿）、認証に関わるもの（ログイン情報、銀行口座、暗号資産の鍵）
- **行動の記録**：どのサイトを訪れたか、誰と連絡したか、いつどこにいたか、何を買ったか
- **つながりの関係**：誰と友人か、誰が情報源か、誰と同居しているか、誰と共同作業しているか
- **能力と資源**：自分の端末、帯域、時間、そして人間関係そのもの

「何を守るか」を具体的に書くことが重要です。「プライバシーを守りたい」は抽象的すぎて、道具の判断には使えません。「ある記者の友人と連絡している事実を第三者に知られたくない」と書けばずっと具体的になり、「受信者が誰かというメタデータを隠す必要がある」という要件に対応づけられます。

## 2 問目：誰から守るのか

敵対者は抽象的な「ハッカー」や「政府」である必要はありません。具体化してください。

- **これを知られると困る相手は誰か。** 親密な関係にある相手か。前の勤務先か。特定の業界の利害関係者か。捜査機関か。外国の情報機関か。
- **その相手が情報を得る能力はどの程度か。**
    - 通りすがりの他人：公開の投稿が見える程度で、それ以上の能力はない
    - 親密な関係にある相手：端末に触れられ、メッセージを読め、習慣もパスワードも知っている
    - 雇用主や学校：業務端末のネットワーク通信を管理でき、組織アカウントを閲覧できる
    - プラットフォーム事業者：自社サービス上の全活動が見え、必要なら法令に従って提出する
    - 一国の法執行機関：事業者に照会でき、必要なら捜索や押収ができる
    - 国家規模の情報機関：大規模な通信監視を行え、特定の標的に狙いを定めた資源を投入できる

この段階分けの目的は、道具の選択を実際の能力の範囲に対応させることです。敵対者が親密な関係にある相手なら、Tor は要りません。要るのは端末のロック、クラウドアカウントのパスワード変更、そして端末位置の共有機能（iPhone の「探す」など）を切ることです。敵対者が大規模なプラットフォーム収集なら、エアギャップの端末（ネットワークに一切つながない隔離された機器）は要りません。要るのは、既定でメタデータを集めない通信手段を選ぶことです。

## 3 問目：どこまでコストを払えるのか

コストはお金だけではありません。

- **時間**：新しい道具を学ぶ、新しい手順を設定する、定期的に保守する
- **利便性**：メッセージを送るたびに操作が増える、起動のたびに長いパスワードを打つ、いちばん便利なクラウド同期が使えなくなる
- **人間関係のコスト**：友人から連絡がつきにくいと言われる、家族に大げさだと思われる、同僚と作業手順をすり合わせ直す
- **金銭**：ハードウェアへの投資（YubiKey、新しい端末）、有料サービス（VPN、パスワード管理ツール）

毎日 2 時間の保守を要し、友人と連絡するたびに変わったソフトを使う理由を説明しなければならない方式なら、数週間で放り出すことになります。**3 か月続かない方式は、方式がないのと同じです。**

脅威モデルの設計目標は、自分が維持できる範囲のなかで脅威にできるだけ対応させることです。続けられない最高等級の防御より、長く維持できる方式のほうが実際には強くなります。

## 手順：3 問を小さなリストに落とす

紙を 1 枚用意するか共同編集の文書を開いて、順に答えてください。

1. 最も守りたい資産を 3 つから 5 つ挙げる（具体的で、指し示せるもの）
2. 資産ごとに、最も可能性の高い敵対者を 1 つか 2 つと、その能力を書く
3. 資産と敵対者の組み合わせごとに、払えるコストの上限を書く（時間、不便さ、金銭）
4. 手持ちの道具や手順を突き合わせ、対応できているもの、足りないもの、過剰なものを見る

このリストは完璧である必要はありません。書き出すことと、定期的に見返すことが要点です。生活の状況は変わります（転職、関係の終わり、機微なテーマへの関与の始まり）。脅威モデルもそれに応じて変わります。

## いくつかの立場ごとの例

以下は粗い見取り図で、**そのまま自分に当てはめることはできません**。考える出発点として使ってください。

### 一般の利用者（とくに機微な仕事はしていない）

- **資産**：日常の通信内容、写真、クラウドアカウント、銀行口座
- **敵対者**：詐欺、プラットフォームからの情報流出、広告トラッキング
- **トレードオフ**：時間の投入は少なく、慣れた道具を使い続けたい、日常の利便性は落とせない
- **対応**：パスワード管理ツールを使う、2 要素認証を有効にする、年に一度は写真ライブラリのメタデータを整理する、心当たりのないリンクを開かない

### 記者（情報源を守る）

- **資産**：情報源の実名、情報源とのやり取りの内容、取材記録、未掲載の原稿
- **敵対者**：報道対象の内部調査、関連業界の法務、必要に応じた捜査機関の照会
- **トレードオフ**：道具の習得に時間を割ける、相応の不便は受け入れられる、予算がある
- **対応**：SecureDrop（情報提供者が報道機関へ匿名で文書を送る仕組み）などを経由して情報源と接触する、ファイルの扱いは Tails で行う、取材記録はオフラインで暗号化する、掲載後に痕跡を整理する

### 社会運動に関わる人

- **資産**：行動の計画、参加者の名簿、現場の写真、弁護士とのやり取り
- **敵対者**：対立する側による身元の特定、職務質問時の端末確認、SNS アルゴリズムによる可視性の低下
- **トレードオフ**：行動の当日に必要になる、仲間を巻き込んで一緒に設定できる
- **対応**：行動前にアカウントを整理する、現場では Signal のグループを使う、機微なデータは端末に置かない、職務質問を受けたときの対応手順を決めておく

### DV から離れようとしている人（離れる前後）

- **資産**：現在の居場所、新しく取得した連絡手段、相談の経緯の記録
- **敵対者**：加害者。あなたの端末のパスワード、家族プランのクラウド権限、共通の交友関係を持っている可能性があります
- **トレードオフ**：相手に気づかれないことが最優先で、外から見た行動はふだんどおりに見える必要があります
- **対応**：加害者が把握していない端末から支援機関に連絡する、共有クラウドアカウントの切り替えは慎重に行う、位置情報の共有設定と「探す」系の機能を確認する

    !!! info "日本の相談窓口"

        - **DV相談ナビ　#8008（はれれば）** — 最寄りの配偶者暴力相談支援センターにつながります
        - **DV相談＋（プラス）　0120-279-889** — 24 時間 365 日の電話相談。チャット相談とメール相談もあり、10 言語に対応しています

        いずれも内閣府男女共同参画局の[DV相談について](https://www.gender.go.jp/policy/no_violence/dv_navi/index.html){target="_blank"}に案内があります。加害者と共有している端末や回線からは履歴が残る可能性があるため、可能であれば別の端末から連絡してください。

この 4 つの違いは、すべて 2 問目の敵対者の能力の違いから来ています。脅威モデルは他人のものを写すことができません。自分の 3 問に戻ってください。

## 脅威モデルは一度作って終わりではない

これは生きているリストです。次のような機会に見返すことをおすすめします。

- 転職、パートナーの変化、引っ越しがあったとき
- 新しく機微なテーマに関わり始めたとき
- セキュリティの事故が起きたとき（自分のものでも、他人のものでも）
- 重要な道具に更新があったとき（Signal に新機能が入る、Tor に大きな更新があるなど）

見返すたびに書き直す必要はありません。「前に書いたことはまだ正確か。新しい敵対者は現れたか。払えるコストは変わったか」を問うだけで十分です。
